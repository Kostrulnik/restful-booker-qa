# Тестирование REST API Restful-Booker

Тестовое задание на позицию QA-инженера. Объект тестирования — открытый учебный сервис бронирования [Restful-Booker](https://restful-booker.herokuapp.com/apidoc/index.html), предоставляющий REST API для CRUD-операций.

В работу входили: анализ документации API, разработка позитивных и негативных тест-кейсов, сборка Postman-коллекции с проверками в Tests и оформление баг-репорта по найденным дефектам.

## Содержимое репозитория

| Путь | Описание |
|---|---|
| `test-cases/test-cases-restful-booker.xlsx` | 76 тест-кейсов по всем эндпоинтам |
| `postman/restful-booker.postman_collection.json` | Коллекция Postman, формат v2.1 |
| `postman/restful-booker.postman_environment.json` | Окружение с переменными |
| `bug-report/bug-report-restful-booker.xlsx` | 12 заведённых дефектов и сводка |

## Покрытие

Протестированы все эндпоинты из задания: `POST /auth`, `POST /booking`, `GET /booking` с параметрами фильтрации, `GET|PUT|PATCH|DELETE /booking/:id`, `GET /ping`.

Всего 76 тест-кейсов: 28 позитивных и 48 негативных. Негативные проверки включают отсутствие обязательных полей, некорректные типы и форматы данных, граничные значения, невалидный JSON, отсутствие и подмену заголовков, работу без авторизации и с недействительным токеном, обращение к несуществующим ресурсам, а также попытки SQL-инъекции и внедрения HTML/JS.

Ожидаемые результаты в кейсах сформулированы по документации сервиса, а там, где она умалчивает, — по стандарту HTTP (RFC 9110). Часть проверок падает намеренно: это и есть зафиксированные расхождения, вынесенные в баг-репорт.

## Как запустить

1. Импортировать в Postman оба файла из папки `postman/`.
2. Выбрать окружение **QA** в правом верхнем углу. Без него переменные `{{baseUrl}}`, `{{username}}`, `{{password}}` не раскроются.
3. Запустить коллекцию целиком через Collection Runner.

Папки пронумерованы в порядке выполнения, запросы внутри идут по порядку ID тест-кейсов. Токен авторизации и идентификаторы созданных броней записываются в переменные окружения автоматически по ходу прогона, поэтому коллекцию следует запускать сверху вниз. Отдельный прогон папок `06`–`08` без предшествующих даст ложные падения: часть кейсов проверяет состояние, созданное предыдущими запросами.

Имя каждого запроса начинается с ID тест-кейса из xlsx — это позволяет сверить коллекцию с документацией построчно. Запросы с префиксами `SETUP` и `CHECK` служебные: они готовят отдельные брони для деструктивных операций и не являются тест-кейсами.
